# Security Audit

Audit date: 2026-10-30. Scope: repository source, config templates, environment file tracking/history metadata, npm/Python dependency manifests, Express endpoints, Flask/LangGraph workflow, browser code, deployment notes, and Markdown files. This is a code/config review plus the tests listed here; it is not a penetration test or production certification.

## Findings and remediation

| ID | Severity | Finding / affected area | Risk | Remediation status |
| --- | --- | --- | --- | --- |
| SEC-01 | High | No prior auth on planner and account routes (`server.js`, chatbot route) | Anonymous users could consume expensive planning and there was no private account boundary. | **Fixed:** registration/login/session middleware; plan routes require user; guest chat plan intent rejected. |
| SEC-02 | High | Flask planner could be called directly if exposed (`multiagent-engine/server.py`) | Network callers could bypass Express account/rate checks. | **Fixed for production:** bearer service token required on `/plan`; keep Flask private. Not exercised in a live production configuration. |
| SEC-03 | High | Historical `docs/KNOWN_ISSUES.md` says a Gemini key may have been pasted in chat | That credential may remain usable if not rotated. | **Open / action required:** rotation status cannot be confirmed from repository. No value is reproduced. Rotate it in provider console and update private environment. |
| SEC-04 | Medium | User/plan ownership and persistence were absent | No way to save plans privately; future IDOR risk. | **Fixed:** local private JSON stores, owner-scoped list/update/delete, ownership tests. Single-process file storage remains a limitation. |
| SEC-05 | Medium | Browser-cookie mutation routes lacked CSRF controls | Cross-site requests could attempt state changes. | **Fixed:** session-bound cookie/header CSRF check on POST/PUT/PATCH/DELETE; same-site cookies and explicit CORS. |
| SEC-06 | Medium | CORS, response headers, body parser, and request volume controls were incomplete | Cross-origin exposure, clickjacking, content sniffing, oversized bodies, and resource exhaustion. | **Fixed in Express:** explicit origin checks, CSP/frame/nosniff/referrer/permissions/HSTS headers, 16 KiB body cap, in-memory rate limits. Limits are per-process. |
| SEC-07 | Medium | Password reset/email verification absent | Users cannot recover accounts; unverified email can be registered. | **Not implemented by design:** no delivery service exists. UI and docs state the limitation. |
| SEC-08 | Medium | Session availability and file-store concurrency | Sessions are memory-only; JSON writes do not coordinate across processes or hosts. | **Open limitation:** production requires persistent private files, but only one process is supported; no shared session store or transactional DB. |
| SEC-09 | Medium | Prompt injection through user queries/retrieved content remains possible (`services/geminiService.js`, LangGraph) | A model may follow malicious instructions or produce misleading output despite system constraints. | **Mitigated, not eliminated:** curated record projection, bounded input, restricted task/system instructions, deterministic planner, structured validations, and no user access to internal graph state. Residual risk remains. |
| SEC-10 | Medium | Local saved plan includes precise start/end coordinates | Unauthorized file access or backup exposure could reveal visit/location data. | **Mitigated:** owner-scoped API, private ignored file, documented restrictive storage/backup handling and 365-day expiry. OS-level deployment permissions were not verified. |
| SEC-11 | Medium | New-style React prototype contains simulated login/OAuth flows | If deployed independently, users could mistake client-only state for authentication. | **Open / not active:** active server UI is Express/EJS; prototype is not the authentication authority. Do not deploy `new_style` auth as access control; wire it to server APIs before use. |
| SEC-12 | Low | MongoDB URI configured without installed driver in runtime | Operators could believe data is stored in MongoDB when the driver was absent. | **Fixed:** Installed official `mongodb` driver (v7.7.0). `config/db.js` connects to MongoDB Atlas with connection pooling, auto-seeds the `pois` collection, and maintains resilient zero-crash fallback to local JSON. |
| SEC-13 | Low | Admin UI, MFA, account suspension, and persisted audit events absent | Admin operations require direct API use; privileged accounts lack a second factor. | **Open:** role checks exist, but higher-assurance admin controls need further work. |
| SEC-14 | Medium | Dependency audit found vulnerable transitive `body-parser` and `qs` versions | DoS conditions in affected dependency ranges. | **Fixed:** `npm audit fix` updated lockfile dependencies; subsequent npm audit reported zero vulnerabilities. |
| SEC-15 | Low | SQL/NoSQL injection checks | There is no SQL/NoSQL engine or query adapter in active path. | **Not applicable to current code:** JSON data uses local ID filters; revisit if a database adapter is introduced. |
| SEC-16 | Medium | UI language coverage for auth | Auth keys use the existing localization loader, but only English strings are added; other languages fall back to English. | **Partial:** integration exists; translated auth catalogs are not complete. |
| SEC-17 | High | External CDN dependency & inline script in `views/results.ejs` | CSP violation under strict `'self'` policy and potential XSS via unescaped inline JSON. | **Fixed:** Replaced unpkg with bundled local `/vendor/leaflet/` assets, isolated JSON in safe `<script type="application/json">` with `<` entity escaping, and moved map controller to external `/js/results-map.js`. |
| SEC-18 | Medium | Missing single-plan retrieval endpoint and IDOR validation | Users could only list plans; fetching an individual plan by ID lacked a dedicated endpoint and ownership verification. | **Fixed:** Implemented `GET /api/itineraries/:id` with strict `userId` ownership check in `itineraryStore.get(userId, id)` returning 404 for foreign or missing IDs without disclosing existence. |
| SEC-19 | Medium | Account-level brute-force credential stuffing | Rate limiting was IP-based only; distributed botnets could target a single email without tripping per-IP caps. | **Fixed:** Implemented account-level failed attempt tracker in `authService.js`. 5 consecutive failed logins lock the account email for 15 minutes (`HTTP 429 AUTH_ACCOUNT_LOCKED`). |
| SEC-20 | Low | Unbounded input lengths in intent controller and LangGraph manager | Massive queries could lead to high token costs or memory pressure. | **Fixed:** Enforced 1000-character ceiling on queries in `intentController.js` and `manager.py`, and bounded interest tags to 10 items of max 100 characters each. |

## Other controls reviewed

- No file-upload endpoint was found; upload risks are not applicable to active routes.
- `.env` and nested dotenv files are ignored and not tracked in the current tree. Git history queries returned no commits containing `.env` or `multiagent-engine/.env`. Values in local env files were not printed. A separate prior chat exposure note remains open as SEC-03.
- No hardcoded provider key pattern was found in non-data source files during a targeted scan. This scan is not proof that all secrets are absent.
- No MongoDB adapter, SQL ORM, database credentials, or row-level security exists. Account and itinerary JSON files use 0600 mode where supported; Windows ACLs were not independently inspected.
- Flask Manager and response stages validate workflow inputs/outputs, but Flask production auth/rate behavior was not exercised with a production deployment configuration.
